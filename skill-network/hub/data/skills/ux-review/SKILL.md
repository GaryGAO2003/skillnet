# 设计稿毒舌评审

把设计稿交给它，得到一份直接、具体、带改法的评审：问题按严重度排序，每条都说清违反了什么、对用户有什么后果、怎么改。

## 什么时候用
- 设计评审前先自查，或者交付前过一遍可用性。
- 想知道某个页面（登录、支付、表单、首页）哪里会让用户卡住。
- 想核对对比度、按钮大小是否达标。
- 不适合：替代真人可用性测试，或判断品牌调性好不好看。

## 先问清楚
信息够就直接做。只有缺下面两项、又无法推断时才问，最多 2 个问题：
1. 这是什么页面或流程，给谁用？平台没说就按手机 App 处理。
2. 有没有色值和控件尺寸？没有也能评，但对比度和点击区域会标成「假设 / 未实测」。

## 怎么做
1. 复述任务：一句话说清这个页面让谁完成什么事，没说就推断并写明。
2. 走一遍流程：按用户视角走，进入 → 看懂 → 操作 → 得到反馈 → 出错 → 完成，记下每个卡点。
3. 对照尼尔森十大可用性原则逐条扫，检查问句见 [references/heuristics.md](references/heuristics.md)。
4. 查硬指标：
   - 对比度：正文 4.5:1；大字（18pt 以上，或 14pt 以上粗体）3:1；图标、输入框边框等界面组件 3:1。给了色值就按公式算。
   - 触控目标：iOS 不小于 44×44 pt，Android 不小于 48×48 dp，相邻目标间距不小于 8 dp（iOS 为 8 pt）；网页至少 24×24 CSS px（WCAG 2.2 的最低要求），触屏上建议更大。
   - 各种状态是否齐全：默认、按下、禁用、错误、加载、空状态。
5. 定严重度：4 灾难（用户无法完成任务或会造成损失）、3 严重（多数用户会卡住）、2 中等（部分用户困扰但能绕过）、1 轻微（影响观感）。
6. 每个问题写五项：位置、现象、违反的原则、对用户的后果、具体改法（尽量给数值、文案或布局）。
7. 也写 2–3 个做得好的地方，最后挑出最该先修的 3 条。
8. 语气：直接、具体，可以带点幽默，对事不对人。每条批评都必须带改法。

## 输出格式
```text
评审对象：{页面 / 平台 / 目标用户 / 关键任务}　信息来源：{截图 / 文字描述 / 色值}（假设的部分单独列出）
一句话判断：{…}

问题清单（按严重度排序）
1. 【严重度 {1–4}】{位置}：{现象}
   原则：{尼尔森第 n 条 / WCAG x.x.x}　后果：{对用户的影响}
   改法：{具体改法，尽量带数值或文案}
2. …

做得好的：{2–3 点}
优先修这 3 条：{序号}
未能核实的：{需要实测或截图的项目}
```

## 质量标准 / 避坑
- 每条问题都要有证据（哪个元素、什么数值）和具体改法，不说「感觉不太好」。
- 只有文字描述时看不到真实画面，对比度和尺寸要么用用户给的数值计算，要么写明「假设 / 未实测」。
- 尼尔森原则是经验法则，不能代替用户测试。重大决策仍然要让真实用户走一遍任务。
- 平台规范（Apple HIG、Material）会更新，以官方最新文档为准。
- 隐私政策勾选、未成年人保护、无障碍法规等合规问题，以法务和平台审核要求为准。
- 毒舌不是夸大：没有依据的问题不提，也不要为了好玩而贬低设计师。

## 示例
**你说**：登录页：手机号 + 密码 + 三个第三方登录

**评审对象**：移动端 App 登录页，目标用户是普通消费者，任务是尽快登录。信息来源：仅文字描述，没有看到画面。假设：主按钮 `#5092F0` 底配白字；输入框提示文字 `#AEAEAE`，用的是占位符（输入后消失）；三个第三方图标 32pt 并排，间距约 4pt；没有设计错误状态。以下涉及数值和状态的地方都按这些假设判断，请用真实设计稿复核。
**一句话判断**：页面很干净，但主按钮像在躲你，第三方登录像在抢戏。

1. 【严重度 3】主按钮「登录」：白字配 `#5092F0` 只有 3.1:1。
   原则：WCAG 1.4.3（按钮文字 16–17pt 常规字重，不算大字，要 4.5:1）　后果：强光或低亮度屏幕下看不清主操作。
   改法：底色改成 `#2062EC`（白字 5.2:1），或保持浅底改用深色字。
2. 【严重度 3】第三方登录：三个图标与主按钮同等醒目，抢了主路径。
   原则：尼尔森第 8 条（视觉层级）　后果：用户分心，主流程完成率下降。
   改法：放到页面底部「其他登录方式」分隔线下，图标统一尺寸、降低视觉权重，只留目标用户常用的 2–3 个。上架 iOS 时，请对照最新审核指南 4.8，核实是否需要提供 Sign in with Apple 或同等选项。
3. 【严重度 2】输入框提示文字：`#AEAEAE` 在白底上只有 2.2:1，而且输入后提示就消失了。
   原则：WCAG 1.4.3、尼尔森第 6 条（识别而非回忆）　后果：用户读不清，输入一半又忘了该填什么。
   改法：提示文字至少用 `#6B6B6B`（5.3:1），并给每个输入框一个固定的顶部标签或浮动标签。
4. 【严重度 2】第三方图标的点击区域：32pt 小于 iOS 的 44×44 pt 和 Android 的 48×48 dp，相邻间距约 4pt，也不足 8。
   原则：尼尔森第 5 条（防错）　后果：容易误点到旁边的登录方式。
   改法：视觉大小可以保持 32pt，但把点击热区扩到 44×44 pt 以上（Android 48×48 dp），相邻间距不小于 8。
5. 【严重度 2】错误状态：描述里没有提到，按没有设计处理。
   原则：尼尔森第 9 条　后果：用户输错后不知道错在哪，只能反复试。
   改法：就地显示在输入框下方，颜色、图标、文案三者同时用，不只靠红色；文案写原因和下一步，例如「手机号少了一位，请检查」「密码错误，还可再试 4 次，或改用验证码登录」。
6. 【严重度 2】默认登录方式：国内多数用户更习惯手机号加验证码，密码容易忘（按常见情况判断，请结合你的数据）。
   原则：尼尔森第 7 条（灵活高效）、第 3 条（用户控制）　后果：多一步找回密码，流失增加。
   改法：默认验证码登录，密码登录作为切换项；密码框加显示 / 隐藏切换和「忘记密码」入口；手机号框唤起数字键盘并按 3-4-4 分段。

**做得好的**：① 元素很少，只有一个主任务，后面改的时候别往里塞东西；② 手机号加密码是用户熟悉的做法，学习成本低；③ 提供第三方登录，给不想记密码的人留了捷径，只需要降低它的视觉权重。
**优先修这 3 条**：1（改一个色值就解决）、2、3。
**未能核实的**：真实色值和控件尺寸、错误和加载状态、深色模式、小屏手机上的排布，请贴截图或 Figma 标注再复核。
