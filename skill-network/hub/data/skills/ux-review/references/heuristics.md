# 可用性评审速查

给 ux-review 用。包含尼尔森十大可用性原则、严重度量表、WCAG 速查和平台规范速查。规范会更新，数值以官方最新文档为准。

## 一、尼尔森十大可用性原则

| # | 原则 | 检查问句 | 常见违规 |
| --- | --- | --- | --- |
| 1 | 系统状态可见 | 用户知道现在发生了什么吗？操作有及时反馈吗？ | 提交后没有加载提示，不知道成功了没有 |
| 2 | 系统与现实世界相符 | 用的是用户的语言和习惯吗？ | 满屏技术术语，图标含义不直观 |
| 3 | 用户控制与自由 | 能撤销、返回、退出吗？ | 弹窗关不掉，误删无法撤销 |
| 4 | 一致性与标准 | 同样的东西长得一样、叫得一样吗？符合平台惯例吗？ | 同一操作在不同页面叫法不同，自创手势 |
| 5 | 防错 | 容易出错的地方有预防吗？ | 危险操作没有确认，输入框不限制格式，按钮挤在一起 |
| 6 | 识别而非回忆 | 用户需要靠记忆才能继续吗？ | 用提示文字代替标签，选项不可见 |
| 7 | 使用的灵活性与效率 | 新手和熟手都方便吗？ | 没有记住账号，没有快捷入口 |
| 8 | 美学与极简设计 | 每个元素都有用吗？重点突出吗？ | 视觉层级混乱，次要信息抢主要信息 |
| 9 | 帮助用户识别、诊断并从错误中恢复 | 错误信息说清原因和解法了吗？ | 只有「操作失败」，没有下一步 |
| 10 | 帮助与文档 | 需要时能找到帮助吗？ | 复杂功能没有引导，帮助藏得很深 |

## 二、严重度量表

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| 4 | 灾难：用户无法完成任务，或会造成数据、金钱损失 | 上线前必须修 |
| 3 | 严重：多数用户会卡住或明显困扰 | 优先修 |
| 2 | 中等：部分用户困扰，但能绕过 | 排期修 |
| 1 | 轻微：影响观感或细节 | 有空再修 |

判断严重度看三件事：影响的用户比例、出现的频率、用户能不能自己恢复。

## 三、WCAG 速查（2.x）

| 条目 | 要求 | 级别 |
| --- | --- | --- |
| 1.4.3 文本对比度（最低） | 正文 4.5:1；大字 3:1。大字指 18pt（24px）以上常规字重，或 14pt（约 18.7px）以上粗体 | AA |
| 1.4.6 文本对比度（增强） | 正文 7:1；大字 4.5:1 | AAA |
| 1.4.11 非文本对比度 | 界面组件（输入框边框、图标、按钮轮廓）和关键图形与相邻颜色 3:1 | AA |
| 1.4.1 使用颜色 | 不能只靠颜色传达信息，要配文字、图标或形状 | A |
| 2.5.8 目标尺寸（最低，2.2 新增） | 指针目标至少 24×24 CSS px（有例外） | AA |
| 2.5.5 目标尺寸（增强） | 至少 44×44 CSS px | AAA |

对比度算法：

```text
每个通道：c = 值 / 255；c ≤ 0.04045 时取 c / 12.92，否则取 ((c + 0.055) / 1.055) 的 2.4 次方
相对亮度 L = 0.2126 × R + 0.7152 × G + 0.0722 × B
对比度 = (较亮的 L + 0.05) / (较暗的 L + 0.05)
```

能运行代码就直接算；不能运行时，白底上的灰字 `#767676` 刚好 4.5:1，比它更浅就不达标，可以作为快速判断的参照。

## 四、平台规范速查

| 项目 | iOS（Apple HIG） | Android（Material） | 网页 |
| --- | --- | --- | --- |
| 最小触控目标 | 44×44 pt | 48×48 dp，相邻间距 8 dp 以上 | WCAG 最低 24×24 CSS px，触屏建议 44×44 |
| 底部导航 | Tab Bar，通常 3–5 项 | Navigation Bar，3–5 个目的地 | 视情况 |
| 正文字号 | 默认约 17 pt，不要小于 11 pt | 常用 14–16 sp | 正文通常不小于 16 px |
| 返回 | 左上角返回按钮加边缘右滑手势 | 系统返回手势或按钮 | 浏览器返回 |
| 安全区 | 避开状态栏、刘海和底部横条 | 避开系统栏和手势区 | 注意移动端浏览器工具栏 |

## 五、评审时好用的小方法

- 5 秒测试：给人看 5 秒再遮住，问「这页让你做什么」。答不上来，说明主任务不突出。
- 眯眼测试：眯起眼睛看，最先看到的是不是最重要的东西。
- 拇指热区：单手使用时，屏幕下半部最容易够到，高频主操作尽量放在这里。
- 状态走查：把默认、按下、禁用、加载、空、错误、成功每种状态都过一遍。
- 文案走查：把按钮上的字连起来读，看用户能不能只靠按钮文案完成任务（避免「确定」「取消」这种含糊的组合，改成具体动作）。

## 六、国内常见场景的提示

- 登录：手机号加验证码是主流，密码登录和一键登录（运营商认证）作为补充；隐私政策与用户协议要清晰可见，勾选方式以合规要求为准。
- 表单：手机号唤起数字键盘，按 3-4-4 分段；错误提示就地显示。
- 支付：金额、收款方和支付方式要在确认前清晰可见，危险操作要有二次确认。
- 弹窗：不要连续弹出，关闭按钮要容易点中；促销弹窗不要遮挡关键操作。
